# 민원 긴급도 분류 시스템

대학 기숙사 시설 민원 게시글을 **일반 / 중간 / 긴급** 3단계로 자동 분류하는 텍스트 분류 프로젝트입니다.

---

## 📌 프로젝트 개요

기숙사 시설 민원은 보통 접수 순서대로 처리됩니다. 그래서 "전등이 깜빡인다"와 "타는 냄새가 난다"가 같은 대기열에 서고, 실제로 위험한 민원이 뒤늦게 확인되는 문제가 있습니다.

이 프로젝트는 민원 텍스트만으로 긴급도를 판정해 **위험 민원을 우선순위 상단으로 올리는 것**을 목표로 했습니다.

| 라벨 | 등급 | 예시 |
|:---:|---|---|
| `0` | 일반 | 문의, 건의, 단순 불편 |
| `1` | 중간 | 전등·에어컨 고장, 부품 교체 요청 |
| `2` | 긴급 | 누전, 타는 냄새, 가스 냄새, 누수, 감전 위험 |

---

## 🗂 데이터

공개 데이터셋이 없어 기숙사 민원 게시판을 **직접 크롤링해 구축**했습니다.

- **수집 대상**: 강원대학교 춘천·삼척·도계 캠퍼스, 국제대학교 기숙사 민원 게시판
- **수집 방식**: `requests` + `lxml` XPath 파싱 (목록 순회 → 상세 본문·작성일 매칭)
- **최종 규모**: **797건**

| 라벨 | 건수 | 비율 |
|:---:|---:|---:|
| 0 (일반) | 225 | 28.2% |
| 1 (중간) | 478 | 60.0% |
| 2 (긴급) | 94 | 11.8% |

> 긴급 클래스가 약 12%에 불과한 **불균형 데이터**라는 점이 이 프로젝트의 핵심 난점입니다.

---

## 🏷 라벨링

수작업 대신 **규칙 기반 → 임베딩 기반 검증** 2단계로 자동 라벨링했습니다.

**1단계 · 형태소 규칙** (`labeling/labeling_v1.py`)
`Kiwi` 로 명사를 추출해 키워드 사전과 매칭하고, "타는 냄새"처럼 형태소로 나누면 의미가 깨지는 표현은 구문 단위로 우선 매칭했습니다.
→ 다만 "불편합니다", "가스레인지" 처럼 **단어만 같고 문맥이 다른 경우 오탐**이 발생했습니다.

**2단계 · 임베딩 검증** (`labeling/labeling_imbeding.py`)
"불", "가스", "연기" 같은 모호한 키워드가 나오면 `jhgan/ko-sroberta-multitask` 로 문장을 임베딩해, 실제 긴급 상황을 서술한 앵커 문장들과 코사인 유사도를 비교합니다. 유사도가 기준 이상일 때만 긴급으로 인정합니다.

```
앵커 문장 예시
- "건물에 불이 났습니다 화재가 발생했어요"
- "가스가 누출되어 폭발할 위험이 있습니다"
- "전선이 노출되어 감전 위험이 있습니다"
```

## 🧠 모델

`title + content` 를 하나의 텍스트로 합쳐 KLUE-BERT를 파인튜닝했습니다.

| 항목 | 값 |
|---|---|
| 베이스 모델 | `klue/bert-base` |
| 클래스 수 | 3 |
| Max Length | 128 |
| Epoch / Batch | 10 / 8 |
| Learning Rate | 1e-5 |
| Weight Decay | 0.01 |
| Warmup Steps | 50 |

### 불균형 대응

긴급 민원은 **놓치는 비용이 오탐 비용보다 큽니다.** 전부 "중간"으로 찍어도 정확도 60%가 나오므로, 손실 함수 단계에서 직접 개입했습니다.

- **Class Weight** `[1.0, 1.5, 7.0]` — 긴급 오답에 7배 페널티
- **Focal Loss** (`gamma=2.0`) — 쉬운 샘플의 기여도를 낮추고 어려운 샘플에 집중
- **긴급 데이터 보강** — 긴급 샘플 43건 추가 수집 후 재학습

> `training_v1.py` = 기본 CrossEntropy / `training_Focal.py` = Focal Loss + Class Weight (최종)

## 📁 프로젝트 구조

```
.
├── crawler/                  # 게시판 크롤러 (사이트별 XPath 대응)
├── labeling/                 # 1단계 규칙 → 2단계 임베딩 검증
├── training/                 # 학습 스크립트 (기본 / Focal Loss)
├── visualization/            # Confusion Matrix · t-SNE
├── data/                     # 수집 원본 데이터
├── trainingset/              # 라벨링 완료 학습 데이터
└── demo_v4.py                # Streamlit 데모
```

## 👤 담당 역할

첫 팀 프로젝트로, **데이터 수집부터 라벨링·학습·시각화·데모까지 전 파이프라인**을 주도적으로 구현했습니다.

- 게시판 구조가 다른 4개 사이트에 맞춰 크롤러를 개별 대응하고 수집 스키마를 통일
- 규칙 기반 라벨링의 오탐을 확인하고, 임베딩 유사도 검증을 추가하는 2단계 파이프라인으로 개선
- 클래스 불균형을 Focal Loss와 클래스 가중치로 접근하고, 데이터 보강 후 재학습
- Confusion Matrix·t-SNE로 결과를 해석하고 Streamlit 데모로 실사용 흐름을 구현
